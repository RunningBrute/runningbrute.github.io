Often during technical interviews with candidates I notice that they have problems explaining how lambda functions work in modern C++. They don't know what the capture list is responsible for and the syntax is sometimes a little confusing for them. This happens more often the less they use this construct in their everyday work.

To visualize it and finally get a better understanding of how lambdas work, it is worth doing the same thing as the compiler.

```cpp
#include <iostream>

int main()
{
    auto emptyOne = [](){};
    emptyOne();

    int value = 42;

    auto captureDataByCopy = [value](){
        std::cout << value << std::endl;
    };

    captureDataByCopy();

    auto captureDataByRef = [&value](){
        std::cout << value << std::endl;
    };

    captureDataByRef();

    int param1 = 13;
    float param2 = 4.2;

    auto withParams = [](int a, float b){
        std::cout << a << " and " << b << std::endl;
    };

    withParams(param1, param2);
}
```

The code above creates and calls several lambdas.

The first one is empty. In the second one we capture a variable by value. Then we capture the same variable by reference. In the last one we don't capture anything, but instead pass two different parameters in the parentheses.

Thanks to [cppinsights.io](https://cppinsights.io/) we can compile our program in a slightly different way. We can see how the compiler transforms our code and get a better idea of what is actually happening underneath the lambda syntax.

```cpp
#include <iostream>

int main()
{
    class __lambda_5_21
    {
    public:
        inline constexpr void operator()() const
        {
        }

        using retType_5_21 = void (*)();

        inline constexpr operator retType_5_21() const noexcept
        {
            return __invoke;
        }

    private:
        static inline constexpr void __invoke()
        {
            __lambda_5_21{}.operator()();
        }
    };

    __lambda_5_21 emptyOne = __lambda_5_21{};
    emptyOne.operator()();

    int value = 42;

    class __lambda_9_30
    {
    public:
        inline constexpr void operator()() const
        {
            std::cout << value << std::endl;
        }

        // private:
        int value;
    };

    __lambda_9_30 captureDataByCopy = __lambda_9_30{value};
    captureDataByCopy.operator()();

    class __lambda_14_29
    {
    public:
        inline constexpr void operator()() const
        {
            std::cout << value << std::endl;
        }

        // private:
        int& value;
    };

    __lambda_14_29 captureDataByRef = __lambda_14_29{value};
    captureDataByRef.operator()();

    int param1 = 13;
    float param2 = static_cast<float>(4.2000000000000002);

    class __lambda_21_23
    {
    public:
        inline constexpr void operator()(int a, float b) const
        {
            std::cout << a << " and " << b << std::endl;
        }

        using retType_21_23 = void (*)(int, float);

        inline constexpr operator retType_21_23() const noexcept
        {
            return __invoke;
        }

    private:
        static inline constexpr void __invoke(int a, float b)
        {
            __lambda_21_23{}.operator()(a, b);
        }
    };

    __lambda_21_23 withParams = __lambda_21_23{};
    withParams.operator()(param1, param2);

    return 0;
}
```

The code above is the output from the previously mentioned website.

At first glance we can see a lot of complicated names and not-so-common syntax. But if we look closer, things start to become much simpler.

The capture list is represented here by members of the generated class. When we capture a variable by value, the generated lambda object contains its own copy of that variable.

```cpp
[value]
```

is roughly represented by:

```cpp
int value;
```

and when we capture by reference:

```cpp
[&value]
```

the generated object contains a reference:

```cpp
int& value;
```

The parameters that we put inside the parentheses are simply parameters of the call operator.

So:

```cpp
[](int a, float b)
```

is roughly equivalent to:

```cpp
void operator()(int a, float b) const
```

This is probably the most important thing to understand about lambdas.

A lambda in modern C++ is an object of a unique, unnamed type generated by the compiler. That object has an `operator()` which contains the code we put inside the lambda body.

In other words, we can think about a lambda as a small functor that the compiler creates for us.

For example, our lambda:

```cpp
int value = 42;

auto captureDataByCopy = [value](){
    std::cout << value << std::endl;
};
```

can be imagined as something similar to:

```cpp
struct MyLambda
{
    MyLambda(int inputValue) : value(inputValue){}

    void operator()() const
    {
        std::cout << value << std::endl;
    }

private:
    int value;
};
```

And then:

```cpp
MyLambda captureDataByCopy(value);
captureDataByCopy();
```

This is obviously not the exact code generated by the compiler. The actual type of a lambda is unique and unnamed, and the compiler is free to implement it differently.

It is simply a useful mental model for understanding what is happening underneath the syntax.

So, remembering that the capture list `[]` is roughly responsible for the state stored inside the lambda object, the parentheses `()` define the parameters of the call operator, and the `{}` contain the body of that operator, we should hopefully never again forget the syntax or what is hiding underneath a lambda.
